🚨 Critical Project Warnings & Architecture Shifts

1. Avoid Unstable/Beta Framework Versions (Prisma) Prisma

The Problem
A significant amount of time was wasted resolving dependency conflicts and unexpected behavior because the project was initialized with an unstable/beta version of Prisma.
The Solution / Rule for Future AI
Never install or use beta/unstable versions of core framework dependencies for a commercial boilerplate. Always verify the stable release channel. 
# Always check the stable version before installing:
npm view prisma dist-tags

# If 'latest' points to an alpha/beta, explicitly install the last stable major version:
npm install prisma@latest-stable @prisma/client@latest-stable

2. Next.js 16: middleware.ts is now proxy.ts Next.js 16

The Problem
In Next.js 16, the traditional middleware.ts file convention was officially renamed to proxy.ts. Attempting to use middleware.ts for `next-intl` routing causes it to silently fail or throw warnings.
The Solution
The file must be named proxy.ts (located at the root or inside src/) and must export a default function. 
// File: src/proxy.ts
import createMiddleware from "next-intl/middleware";
import { routing } from "./shared/i18n/routing";

export default createMiddleware(routing);

export const config = {
  matcher: ["/", "/(ar|en)/:path*"],
};

🏗️ Tooling & Build Setup Difficulties

3. Tailwind v4 @theme Parse Error Tailwind v4

The Problem
Adding a bare @theme { ... } block caused 18 CSS errors in VS Code and threw an Unknown at rule: @theme warning during npm run dev. The CSS failed to compile.
The Solution
Created postcss.config.mjs with the correct plugin. Changed the static brand values to live in :root, and used @theme inline { } to map them to Tailwind utilities.

4. next lint Command Removed Next.js 16

The Problem
Running next lint in the terminal resulted in CommandNotFoundException.
The Solution
Next.js 16 deprecated the built-in wrapper. Run npm run lint (which calls eslint directly) or npx eslint ..
⚛️ React 19 & Next.js 16 Difficulties

5. Hydration Mismatch & set-state-in-effect Lint Error React 19

The Problem
Zustand's persist middleware rehydrates the cart from localStorage before the first client paint, causing a server/client mismatch for the cart badge. Using useEffect(() => setIsMounted(true), []) to fix it triggered React 19's new react-hooks/set-state-in-effect error.
The Solution
Replaced the effect with useSyncExternalStore. It provides an SSR-safe way to detect the client without triggering a cascading state update.

6. Unconfigured External Image Host Next.js

The Problem
The browser threw: Invalid src prop (https://flagcdn.com/...), hostname "flagcdn.com" is not configured under images in your next.config.js.
The Solution
Added flagcdn.com to the remotePatterns array in next.config.ts.

🎨 UI & CSS Difficulties

8. Undefined Utility Classes in LanguageSwitcher Tailwind

The Problem
The Phase 0 LanguageSwitcher used classes like bg-card, text-accent, and border-border which were not defined in Tailwind, resulting in invisible text and missing backgrounds.
The Solution
Defined these exact tokens in @theme inline within globals.css and mapped them to the new semantic CSS variables.

9. RTL Positioning with Logical Properties Tailwind

The Problem
The cart badge positioning needed to flip perfectly between LTR and RTL.
The Solution
Used Tailwind v4 canonical logical properties: -inset-e-1 (negative inset-end) instead of the older -end-1.

10. VS Code False-Positive Squiggles VS Code

The Problem
Despite the app compiling perfectly, VS Code's Problems tab remained full of red errors. Nesting properties inside files.associations caused a type mismatch.
The Solution
Placed settings at the root level of .vscode/settings.json and used "css.lint.unknownAtRules": "ignore".
🧠 Developer Cheat-Sheet & Pro-Tips
  • Next.js 16 Middleware: It is no longer middleware.ts. Rename the file to proxy.ts and export the default function.
  • Prisma Dependencies: Always check if Prisma is in a beta or unstable state before initializing. A commercial boilerplate must rely on the latest stable release.
  • React 19 Hydration: Never use useEffect(() => setMounted(true), []). Use useSyncExternalStore to safely render client-only data (like Zustand persisted state) without hydration mismatches.
  • Tailwind v4 Setup: You must have a postcss.config.mjs with "@tailwindcss/postcss": {}. Do not use the old @tailwindcss/turbopack plugin.
  • Tailwind v4 Theming: Define raw colors in :root { --primary: #c9a961; }. Map them to utilities using @theme inline { --color-primary: var(--primary); }.
  • Next.js 16 Linting: The next lint command is dead. Use npm run lint or npx eslint ..
  • Next.js Env Vars: Variables prefixed with NEXT_PUBLIC_ are baked into the client bundle at startup. You MUST restart the dev server to see changes to these variables.
  • RTL Best Practices: Never use ml-, mr-, left-, or right-. Always use logical properties: ms-, me-, ps-, pe-, and inset-s- / inset-e-.
  • VS Code & Tailwind v4: If Tailwind v4 shows red squiggles in VS Code but the app compiles perfectly, trust the terminal. Fix VS Code by adding "css.lint.unknownAtRules": "ignore" to workspace settings.
