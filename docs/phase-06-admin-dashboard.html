🛡️ Authentication & Security

1. Middleware & Prisma Incompatibility NextAuth v5

The Problem
Next.js Middleware runs on the Edge Runtime, which does not support Prisma or Bcrypt. Attempting to run the full Auth config inside proxy.ts caused build errors.
The Solution
Split the configuration. auth.config.ts contains only Edge-compatible settings (routes, callbacks), while auth.ts contains the Prisma Credentials provider.

2. JWTSessionError: No Decryption Secret NextAuth v5

The Problem
The console threw JWTSessionError: no matching decryption secret because the AUTH_SECRET was missing from the environment variables.
The Solution
Added AUTH_SECRET="a_very_long_random_string_at_least_32_characters_long_12345" to .env and restarted the dev server.
🌍 i18n & Admin UI

3. Missing Admin Translations next-intl

The Problem
The Admin dashboard was hardcoded in English, breaking the bilingual requirement of the boilerplate.
The Solution
Added AdminAuth, AdminLayout, and AdminOrders namespaces to both JSON files. Injected getTranslations into the Server Components and useTranslations into the Client Login form.

4. Hidden Logout Button Next.js

The Problem
The logout button was being pushed off-screen if the orders table was too long, making it inaccessible.
The Solution
Changed the Admin Sidebar to sticky top-0 h-screen and used flex-1 on the navigation to ensure the Logout button always stays pinned to the bottom.
🧠 Developer Cheat-Sheet & Pro-Tips
  • Session Persistence: If you try to visit the login page while logged in, NextAuth will automatically redirect you to the dashboard. This is a security feature. To test the login page, click the "Sign Out" button.
  • NextAuth v5 Splitting: Always keep Prisma and Bcrypt out of auth.config.ts. Only use that file inside the Middleware/Edge runtime.
  • Sticky Admin Sidebars: Use sticky top-0 h-screen flex flex-col on the sidebar, and flex-1 on the navigation links. This guarantees the logout button is always visible at the bottom of the screen.
  • Server-Side Auth Guard: Even with middleware, always call const session = await auth(); if (!session) redirect("/login"); inside protected Server Pages (like the orders page) for defense-in-depth.
