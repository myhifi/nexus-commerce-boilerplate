🏗️ Difficulties & Fixes

1. Cascade Deletion Data Loss Prisma

The Problem
Deleting a category silently deleted all products inside it because the Prisma schema used onDelete: Cascade.
The Solution
Changed the schema to onDelete: Restrict and implemented a manual _count check inside the Server Action to block the deletion and return an error message.

2. Missing Admin Localization next-intl

The Problem
The Admin tables were rendering the Arabic name even when the dashboard was switched to English.
The Solution
Added a getDisplayName helper function inside the Server Components to conditionally render nameEn when locale === 'en'.

🧠 Developer Cheat-Sheet & Pro-Tips
  • OnDelete Rules: Use Restrict instead of Cascade when building multi-tenant e-commerce systems. Deleting a category should never silently delete products. Force the admin to explicitly reassign them first.
  • Dynamic Localized Names: Always use fallback logic in multi-language apps: locale === 'en' && entity.nameEn ? entity.nameEn : entity.name.
  • Prisma Migrations vs. Push: During rapid prototyping, prisma db push is safe and fast. When ready to deploy, run prisma migrate reset to generate clean SQL migration files.
