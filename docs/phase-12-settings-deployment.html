🏗️ Difficulties & Fixes

1. Navbar Read from ENV, Not Database Next.js

The Problem
The Settings page saved the store name to the database, but the Navbar was still reading from storeConfig.branding.name (which reads NEXT_PUBLIC_STORE_NAME from .env). This made the Settings page useless for branding.
The Solution
Added a getStoreSettings function using unstable_cache with a store-settings tag. The Layout now fetches the store name from this cache and passes it to the Navbar as a prop. Saving settings calls revalidateTag("store-settings") to invalidate the cache.
🚀 Production Deployment Guide

Deploying Nexus Commerce to Vercel

Step 1: Prepare Your Repository
git push origin main
Step 2: Import to Vercel
  1. Go to vercel.com/new
  2. Import your GitHub repository
  3. Framework Preset: Next.js
Step 3: Environment Variables (Vercel Dashboard)

Copy all keys from .env and add them in Vercel's "Environment Variables" section:

# App
NEXT_PUBLIC_APP_URL=https://your-production-url.vercel.app
NEXT_PUBLIC_STORE_NAME=Nexus Commerce
NEXT_PUBLIC_BUSINESS_TYPE=RETAIL
NEXT_PUBLIC_STORE_TIER=ENTERPRISE
NEXT_PUBLIC_CURRENCY=USD

# Database (Supabase Production)
DATABASE_URL=postgresql://...pooler.supabase.com:6543/postgres?pgbouncer=true&sslmode=no-verify
DIRECT_URL=postgresql://...pooler.supabase.com:5432/postgres

# Auth
AUTH_SECRET=your-production-secret-at-least-32-chars

# Supabase
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

# Email
EMAIL_PROVIDER=resend
RESEND_API_KEY=re_...
EMAIL_FROM=Nexus Commerce <noreply@yourdomain.com>

# Stripe (LIVE KEYS)
STRIPE_SECRET_KEY=sk_live_...
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_live_...
STRIPE_WEBHOOK_SECRET=whsec_...

# Node
NODE_ENV=production
Step 4: Database Migrations

After the first deploy, run migrations against production:

npx prisma migrate deploy
npx prisma db seed  # Only on first deploy
Step 5: Stripe Webhook (Production)
  1. Go to Stripe Dashboard → Developers → Webhooks
  2. Click "Add endpoint"
  3. Endpoint URL: https://your-domain.vercel.app/api/webhooks/stripe
  4. Events: checkout.session.completed and checkout.session.async_payment_succeeded
  5. Copy the whsec_... signing secret into Vercel's STRIPE_WEBHOOK_SECRET
  6. Redeploy to load the new secret
Step 6: Domain Setup
  1. Vercel Dashboard → Domains → Add your client's domain
  2. Update the client's DNS records as shown by Vercel
  3. Wait for SSL provisioning (usually 1-2 minutes)
Step 7: Post-Deployment Verification
  • Visit the production URL and confirm the Navbar renders
  • Test the locale switcher (EN/AR) and RTL
  • Log in as admin and access /admin
  • Place a test order using a real Stripe test card 4242 4242 4242 4242
  • Confirm the webhook fires in the Stripe Dashboard
  • Verify the order appears in /admin/orders with status "PAID"
  • Check the confirmation email arrives
  • Update store name in Settings and verify it reflects instantly
🏷️ White-Label & Multi-Client Onboarding Checklist

Complete Client Delivery Workflow

This is the end-to-end process for delivering a new client site using Nexus as the foundation.

Phase A: Clone & Configure (15 minutes)
  • Clone the boilerplate into a new GitHub repo per client
  • Update .env with the client's Supabase, Stripe, Resend credentials
  • Set NEXT_PUBLIC_STORE_NAME and NEXT_PUBLIC_BUSINESS_TYPE
Phase B: Brand Customization (30 minutes)
  • Update CSS variables in src/app/globals.css (colors)
  • Replace logo in public/
  • Update messages/en.json and ar.json for brand copy
Phase C: Data Seeding (10 minutes)
  • Update prisma/seed.ts with the client's categories and products
  • Update the default admin email/password in prisma/seed.ts
  • Run npx prisma migrate deploy && npx prisma db seed
Phase D: Deploy & Handoff (20 minutes)
  • Deploy to Vercel following the guide above
  • Set up the Stripe production webhook
  • Log in as the client admin and verify all settings
  • Hand over credentials to the client with the Settings documentation
🧠 Developer Cheat-Sheet & Pro-Tips
  • Dynamic Branding: The Navbar's brand name comes from the Setting table (fallback to storeConfig.branding.name). The nav links (Shop/Menu) come from businessType. Never conflate the two.
  • unstable_cache: Use unstable_cache with a tag when reading from the DB in Server Components that render on every page (like the layout). This prevents an extra DB query per request while still allowing invalidation on settings updates.
  • Environment Variables: On Vercel, NEXT_PUBLIC_* variables are baked at build time. Change one = trigger a new deployment.
  • Stripe Webhook Security: Always verify the whsec_... signature. Never accept a POST on the webhook route without it — otherwise attackers can forge "paid" events.
  • Prisma Production: Use prisma migrate deploy (not migrate dev) in CI/CD. Never run migrate reset in production — it will wipe all data.
