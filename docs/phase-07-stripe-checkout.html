💳 Stripe Integration

1. Strict Stripe API Versioning Stripe

The Problem
The Stripe SDK threw a TypeScript error: Type '"2025-02-24.acacia"' is not assignable to type '"2026-10-28.endive"'. Stripe frequently updates its API versions, which breaks hardcoded strings.
The Solution
Removed the hardcoded apiVersion property entirely from the Stripe client initialization. This tells Stripe to use the default API version configured in the Stripe Dashboard, making the boilerplate future-proof. 
// src/shared/lib/stripe.ts
export const stripe = new Stripe(env.STRIPE_SECRET_KEY!, {
  typescript: true,
});
🛡️ Webhook Security

2. Webhook Idempotency & Price Verification Stripe Prisma

The Problem
If the network drops, Stripe might send the checkout.session.completed event multiple times. Without guards, this would create duplicate orders and send duplicate emails. Additionally, we must verify the amount paid matches the DB.
The Solution
Inside the webhook, we query the database for the stripeSessionId before creating the order. We also verify session.amount_total against our recalculated total to prevent tampering.

3. Skipping Local Stripe CLI Next.js

The Problem
The Stripe Webhook route requires an external endpoint to receive data. Without running stripe listen, local payments won't trigger the webhook, and orders won't be saved during local testing.
The Solution
Since this is a boilerplate, local webhook testing can be skipped. The code is production-ready. When deployed to Vercel, the user will add the production URL to the Stripe Dashboard, and the webhook will function perfectly.
🧠 Developer Cheat-Sheet & Pro-Tips
  • Next.js Route Handlers: Use route.ts inside /app/api/ for webhooks. You must read the raw body via await req.text() (not req.json()) so Stripe can verify the signature.
  • Stripe CLI: For local testing of webhooks, run stripe listen --forward-to localhost:3000/api/webhooks/stripe. It provides a whsec_... secret that changes every time you restart the CLI.
  • Webhook Idempotency: Always check if the stripeSessionId already exists in your database before creating an order. Stripe guarantees "at-least-once" delivery, meaning duplicates are possible.
  • Success Page Side Effects: Use a tiny Client Component (SuccessClient.tsx) on the success page to clear the Zustand cart. Server Components cannot mutate client-side state.
