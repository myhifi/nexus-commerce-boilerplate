🌍 i18n & Emails Difficulties

1. Email Lost the User's Language next-intl

The Problem
The order confirmation email was sent in English even though the user checked out in Arabic. The Server Action didn't know what language the user was browsing in.
The Solution
Passed the locale through the FormData: <input type="hidden" name="locale" value={locale} />. The Server Action extracts it and passes it to the email function.

2. Missing Email Translation Key next-intl

The Problem
The console threw MISSING_MESSAGE: Could not resolve Email.OrderConfirmation.labelShippingAddress. The React Email component expected a different key than what was in the JSON file.
The Solution
Opened the JSON files and found labelDeliveryAddress was used instead. Replaced it with labelShippingAddress to match the component's prop.
🚚 Order Tracking

3. RTL Timeline Logic Next.js

The Problem
Ensuring the visual order status timeline (e.g., Pending -> Delivered) renders correctly in RTL (right-to-left) without manually reversing the array.
The Solution
Used CSS Flexbox combined with the dir="rtl" attribute on the HTML. Flexbox naturally reverses the visual order, while the logical index (0, 1, 2...) remains correct in the React array.
🧠 Developer Cheat-Sheet & Pro-Tips
  • Passing Context to Server Actions: Server Actions don't have access to the URL or request context directly. If you need the user's locale, use hidden inputs in the form.
  • React Email in Server Actions: You can render and send React components directly inside Server Actions. It runs asynchronously, so ensure you await the email send before returning the success state to the client.
  • Visual Timelines: Using absolute positioning for the connecting line and flexbox for the nodes makes it extremely easy to build a responsive, RTL-compatible timeline.
  • Preventing 404s: When building a tracking page, always use notFound() if the order ID doesn't exist in the database. This prevents server errors and gives a proper 404 page.
